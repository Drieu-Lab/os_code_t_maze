# Programs & run commands

A quick reference of every runnable program in this repo, what it does, and how
to launch it from Anaconda. The conda env is **`drieu_t_maze`**.

> Keep this file current: whenever a program is added, removed, or its launch
> command changes, update the relevant table below. (See `AGENTS.md`.)

## Setup (once per terminal)

```
conda activate drieu_t_maze
```

The PC tools are an installable package **`tmaze`** (source under `host/tmaze/`;
see [ADR-0083](docs/decisions/0083-host-tools-become-tmaze-package.md)). Install
it editable once per machine (from the repo root) so `python -m tmaze...` works
from any directory:

```
pip install -e .
```

The `python -m tmaze.<layer>.<name>` commands below then run from anywhere; the
`.bat` launchers (`start_rig.bat`, `run_tests.bat`) are run from `host/`.

## Host tools (Python)

Start the serial **broker** first; the GUIs are TCP clients of the broker and
need it running. Run each in its own terminal (or use the launcher below). Every
tool is a package module (`python -m tmaze.<layer>.<name>`), so they need
`pip install -e .` once per machine (from the repo root) and run from any
directory (ADR-0083). The `test_*` unit tests live in `host/tests/`; run them
with `run_tests.bat` (below) or `python -m unittest tests.test_<name>`.

| `sync_fit` (`tmaze.tools`) | The production board-LED video<->Arduino clock sync (design doc `docs/design/cross-stream-sync-design.md` §3, FW-0045; ADR-0153); the thin shell over `tmaze.vision.led_detector` (pixels) + `tmaze.core.sync` (matching/fit). On a recorded session bundle it **self-calibrates the ROI** - detects the persistent red/green fiducial LEDs and uses their convex hull as the board region the blinking LEDs are searched inside (so a hand/rat elsewhere never floods the blob list) - binds each blinking LED to its serial channel, fits `cam_timestamp = offset[seg] + rate*firmware_ms`, and **writes two artifacts into the bundle's `sync/`**: `led_events_<id>.csv` (one row per matched LED edge) and `clock_fit_<id>.json` (per-segment offset/rate, residual + host-lag stats, per-LED verdicts, fiducial counts + board pose, registration transform, board_poly, `method: led-fit`). When a v2 `host/led_map.json` exists it registers the fiducials (colour-constrained) against it to recover the board pose and locates each mapped LED by the HYBRID rule (a detected blob else its pose-transformed stored position); a v1 map falls back to registering the blinking constellation; without any map it **bootstraps** the bindings from the session itself and warns. `--map` builds a v4 `host/led_map.json` (fiducials + board_poly + optional board_search_poly + LEDs + the reference sensor polarity + a per-LED bleed matrix) from a session in TWO passes - pass 1 binds the easy blinking LEDs and fits the clock, pass 2 finds every channel's LED(s) from its serial events (during-minus-quiet-before images), as many per channel as `host/led_board_layout.json` says (`--layout <file>`; beams/licks 2 = `_a` bright row / `_b` dim row, rewards 1), drops fiducials sitting on a channel LED, prints warnings for shortfalls/misplaced pairs, and shows progress for each of its three video reads (ADR-0196) - and writes a QA overlay PNG beside it; `--overlay` writes that debug PNG (ROI + fiducials + LEDs on a still, to eyeball against the physical marker corners) on a normal run too; `--board-rect X0 Y0 X1 Y1` confines the search to a rectangle (fast path / fallback); `--board-poly <file>` confines it to an operator-drawn POLYGON (a normalized `polygon_norm` JSON drawn in the Tracking tab's "Define LED board region", default `host/led_board_search.json`), which excludes maze corners a rat crosses and is baked into the map on `--map` (ADR-0195); `--serial <log>` reads events from a given log instead of the bundle's central-only capture (use the full `rig_logger` CSV for a mapping session, whose left/right-reward and rinse/drain valve acks the capture drops); `--dry-run --out <dir>` prints the report and writes the artifacts to a scratch folder instead of the bundle; which beam/lick wire state counts as ACTIVE is resolved per bundle (its `format.json` `sensor_polarity`, else `legacy_inverted` for a pre-flag bundle, else read off the serial log - the brief state is the active one; refused when none is conclusive) and recorded in `clock_fit_<id>.json`, and `--sensor-polarity {corrected,legacy_inverted}` overrides it (ADR-0199); with a v4 map, the layout file's one-active groups (beams, licks, reward valves) keep only the strongest channel of a group active on each frame, so light spilling between neighbouring LEDs is not read as a second event; `clock_fit_<id>.json` records what it did under `one_active` and the report warns when two channels were really lit at once, and `--no-one-active` turns it off for a run (ADR-0201, ADR-0203); with a map, an LED that matches a channel other than its map channel is reported ("map says X, matched Y") and kept out of the clock fit, recorded under `map_check`, and `--no-map-check` turns that off for a run (ADR-0202); `--selftest` checks the core end to end on synthetic data (no video, no OpenCV). On a normal (non-`--dry-run`) run it also **registers the two `sync/` files in the bundle's `session_<id>.json` manifest** (`sync_led_events`/`sync_clock_fit` streams), flips the time-anchor `fiducial.method` to `led-fit` (keeping the FW-0018 hardware-sync `pending` note), and appends an append-only `post_hoc` edit entry recording the change (the post-Stop manifest edit contract, ADR-0189); the stream + `format.json` bumped to `format_version 2` and `led_map.json` is snapshotted into `config/` at Session Start (ADR-0154). `--overlay` additionally writes a clock-fit QA plot `sync/clock_fit_<id>.png` when the optional `matplotlib` is installed (skipped otherwise). **`--all`** is the batch mode (ADR-0188): fits EVERY bundle under the given root (or the tracked recordings roots when none is given), skipping bundles that already carry a clock fit unless `--refit`; each lands in one of `fit` / `failed` / `skipped` (no video/data, no fiducials, or already fit), prints each bundle's result as it finishes plus a final table + summary, writes a run log, and exits non-zero only when a bundle FAILED (an unexpected error in one bundle marks it failed and the batch carries on). **`--all --dry-run`** touches no bundle: each one's artifacts, `report.txt` and fit plot go to `--out/<session id>/` (default `<recordings root>/_sync_dryrun_all_<date>_<time>/`) with the batch log beside them, and each summary line flags map contradictions / one-active conflict frames / a polarity disagreement for review. A GOOD fit flips `fiducial.method` to `led-fit`; a FAILED fit records the files but leaves it `host-t0`, so the manifest never claims a fit the numbers don't support. Needs `opencv-python`, `numpy` (except `--selftest`; `matplotlib` optional, only for the `--overlay` fit plot). | `python -m tmaze.tools.sync_fit <bundle_dir> [--map] [--overlay] [--board-rect X0 Y0 X1 Y1] [--board-poly <file>] [--layout <file>] [--no-one-active] [--serial <log>] [--sensor-polarity corrected|legacy_inverted] [--dry-run --out <dir>] [--start-min 0] [--minutes 0] [--tol-ms 200] [--min-matched 3] [--min-pairs 30]` · `python -m tmaze.tools.sync_fit --all [--refit] [<root>]` · `python -m tmaze.tools.sync_fit --selftest` |

## Offline analysis (moved to its own repo)

The offline, cross-session **behavioural analysis** layer - the `tmaze.analysis`
package (bundle reader, strategy signals, choice model, trajectory/VTE kinematics),
the interactive notebooks (`animal_progress`, the grant-proposal `proposal_figures`),
and the Parquet / NWB interchange exporters - was carved into its own,
separately-versioned repository, **`drieu_lab_analysis`** (import root
`tmaze_analysis`), per [ADR-0142](docs/decisions/0142-analysis-core-decoupling-data-contract.md)
and FW-0048. It reads the session bundles this rig writes but never imports the
rig code; the coupling is the on-disk bundle **format** (`config/format.json` +
the version guards), kept honest by the shared golden fixture (see
`tools/make_golden_bundle.py` and `test_golden_bundle` above). Install and run
those programs from that repo (`pip install -e .` there; `python -m tmaze_analysis.export_parquet ...`,
`jupyter lab notebooks/animal_progress.ipynb`).
