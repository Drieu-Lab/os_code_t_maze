# Programs & run commands

A quick reference of every runnable program in this repo, what it does, and how
to launch it from Anaconda. The conda env is **`drieu_t_maze`**.

> Keep this file current: whenever a program is added, removed, or its launch
> command changes, update the relevant table below. (See `AGENTS.md`.)

## Setup (once per terminal)

```
conda activate drieu_t_maze
```

The PC tools are an installable package **`tmaze`** (source under `host/tmaze/`;
see [ADR-0083](docs/decisions/0083-host-tools-become-tmaze-package.md)). Install
it editable once per machine (from the repo root) so `python -m tmaze...` works
from any directory:

```
pip install -e .
```

The `python -m tmaze.<layer>.<name>` commands below then run from anywhere; the
`.bat` launchers (`start_rig.bat`, `run_tests.bat`) are run from `host/`.

## Host tools (Python)

Start the serial **broker** first; the GUIs are TCP clients of the broker and
need it running. Run each in its own terminal (or use the launcher below). Every
tool is a package module (`python -m tmaze.<layer>.<name>`), so they need
`pip install -e .` once per machine (from the repo root) and run from any
directory (ADR-0083). The `test_*` unit tests live in `host/tests/`; run them
with `run_tests.bat` (below) or `python -m unittest tests.test_<name>`.

| `rig_broker` (`tmaze.io`) | Owns the Arduino Due's COM port and fans its serial stream out over TCP `localhost:5555`. Run this first. Defaults to `COM3`, the Due's **Programming port** - opening it resets the board, so starting the broker begins a fresh firmware session (ADR-0065). Watch its console during a run: it bounds every write and probes a quiet port with `STATUS`, so a frozen Due is reported as `DUE NOT RESPONDING` within ~25 s (press RESET on the Due; see ADR-0062). `--probe-quiet/--probe-interval/--probe-dead` (seconds) tighten that schedule when chasing a lockup. It also logs the Due's own clock - the firmware session clock when the port opens, and the last line's `ms` when a write fails - so a lockup is timestamped on the board's clock without a logger attached (ADR-0064). | `python -m tmaze.io.rig_broker --port COM3` |

## Firmware (Arduino Due)

Flashed onto the Due with the Arduino IDE rather than run from the PC: open the
`.ino`, select the board entry **Arduino Due (Programming Port)** and that COM
port, then upload. Matching the board entry to the socket the cable is in matters
- picking the Native entry runs a 1200-bps touch that the Programming port does
not answer. The console lives on the Programming port (ADR-0065).

|--------|-------------|
